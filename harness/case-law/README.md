# 判例

`rules/` から切り出した**実例**の置き場。規範と判例の分け方は `rules/process.md`「規範と判例を分ける」。

**いまここにある実例は、すべて移植元（design-composer）で起きたもの。** このリポジトリで
起きた実例はまだ 1 件も無い。`TypographyToken` `denyingIpc` のような、このリポジトリに
存在しないシンボル名が出てくるのはそのため。読むときは形だけを取る。

## なぜ分けるか

**判例は毎回増え、規範は増えない。** 同じファイルに置くと総量が単調増加し、常時ロードされる
`rules/` が膨らみ続ける。移植元では、分ける直前の `rules/` が 1,065 行あり、うち NG/OK 表・
実シンボルの名指し・PR 番号への言及が 4 割近くを占めていた。

もう 1 つの理由は**リポジトリ特化**。上のようなそのリポジトリにしか無い名前が規約本文に
混ざると、規約が「別のリポジトリへ持っていけないもの」になる(判断軸は `rules/process.md`)。

## 誰がいつ読むか

| 読む人 | いつ |
| --- | --- |
| `plan-reviewer` / `implementation-reviewer` | 検証のたび（`rules/` と対で読む） |
| 実装するエージェント | **その分類で実際に迷ったとき / 指摘を受けたとき**だけ |

常時ロードはしない（取り込む側の入口ファイルの `@` import に入れない）。**入れた時点で分けた意味が消える。**

## 誰が書くか

**判断を書くのは `harness-growth` だけ**（`.claude/skills/harness-growth/`）。判断は、起きたこと・
NG / OK の形・判定の分かれ目・機械化できるかの結論を指す。記録から判例へ昇格させるのは
介入の一形態なので、`harness-record` は触らない（規範も変えないので、下の写し・参照の直しも起きない）。

- 判例は**分類タグ**（`harness-record/templates/record.md`「分類の語彙」）で引けるようにする
- **過去の判断を書き換えない。** 判断が変わったら新しい判例を足し、古いほうに「この判断は
  <PR> で更新された」の 1 行を添える
- 規範の写し・規範への参照は判断ではなく、規範に合わせて直すのは書き換えに当たらない。規範を
  変えた回のスキル（`implementation-flow` / `harness-growth`）が直し、食い違いを見つけた回も
  その PR で直してよい（→「判例の外の文書を変えたとき」）
- 判断を書くときは規範の文を写さず、規範の節名で参照する（写しを増やさない）

## 判例の外の文書を変えたとき

判例ファイルと記録（`harness/case-law/` の各判例と `harness/records/`）の外にある文書の、既存の文・
節名・語の意味を変える／消す回は、判例に残るその写し・参照を**同じ PR で**直す。規範の役を持つこの
README 自身も対象に含める。移植元（design-composer #938）で規範を変えた際、判例が追いつかないまま
マージされ、#952 まで食い違いが残った。

1. **探す。** 変える前の文から 10 字ほどの句を取り、`grep -rn '<句>' harness/case-law/` で引く。
   判例は全角括弧で写し、途中で折り返すので、括弧・`**`・行末をまたがない位置で切る。節名を
   変えるなら `grep -rn '「<旧い名前>」' harness/case-law/`。語に新しい意味を与えた・意味を
   狭めたなら、その語でも引く
2. **分ける。** 行ではなく句の単位で見る。判断の文の中にある節名・規範の語は参照として直してよく、
   判断の結論は変えない。判断の中身（結論）をどう扱うかで迷ったら判断として扱う
   - 写し（規範の文をなぞるだけ）→ 消す。写し元が常時ロード（`rules/`）の外なら、写し元の節への
     参照 1 行に置き換える。新しい文へ写し直さない
   - 参照（節名・規範の語）→ 新しい名前・語に合わせる
   - 判例が独自に付けた語が規範の新しい意味とぶつかる → 語だけを直し、判断は変えない
   - 判断 → 書き換えない（「誰が書くか」）

規範から判例へ移した文（`harness-growth`「Step 3: 棚卸し」）は写しではない（移した先が原本）。

フックにしないのは、規範から判例へ移した文と意味を変えた文が字面では区別できないから。移植元で、
判例ができて以降 `rules/` を触ったマージ 29 本で再生すると（変えた規範の文と判例の行の 20 字以上の
一致で数えた）12 本で当たり、追随が要ったのは 1 本だけだった。
