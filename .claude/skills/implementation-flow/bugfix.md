# `flow:bugfix`: 再現を先に固定してから直す

`flow:bugfix` の Issue で、`SKILL.md` の各フェーズに**足す**手順。書いていないフェーズは
`SKILL.md` のまま。

**修正より先に、症状を再現して落ちるテストを書いてコミットする。** 修正と同時に書いたテストは、
修正前のコードで落ちたかが誰にも分からない。直したつもりで別の箇所を直していても通る。

## フェーズ 1: ゴールに症状を書く

ゴールに加えて、**症状を 3 つに分けて** Issue に書く。

- 再現手順(どの入力・操作・状態から)
- 期待する結果(拠り所の設計ドキュメント・`rules/` の節があれば添える)
- 実際の結果

この 3 つは `.github/ISSUE_TEMPLATE/bug.yml` の欄にも写してある。変えたら揃える。

再現手順が書けないなら、ゴールが決まっていない(`SKILL.md` フェーズ 1 のとおり止める)。

## フェーズ 3: 計画の先頭に再現テスト

テストケースの一覧の**先頭**に再現テストを置き、次を書く。

- 置くファイルと、テストの名前(仕様の文。`rules/testing.md`)。このリポジトリのフックなら
  判定表(`*-cases.sh`)のケース
- 再現テストを走らせる検査(このリポジトリでは `harness/githooks/pre-push` が呼ぶ判定表。
  ソースを持つ取り込み側では、その言語のテストランナー)
- 修正前のコードで、**どの assert がどの値で落ちるか**(期待した値と、実際に出る値。判定表なら
  そのケースの期待と実際)
- **今ある公開 API だけで書く。** 修正で足す API を呼ぶと、修正前は「見つからない」「読み込めない」で
  落ちて assert まで届かない
- **第 2 工程(修正)で書き換える既存テストと同じファイルに置かない。** 同じファイルだと、
  `SKILL.md` フェーズ 5 の `git diff --exit-code` が再現テストの書き換えと既存テストの書き換えを見分けられない
- **自動テストで再現できないなら、その理由と代わりの確かめ方**(手で走らせる手順と、症状が出る/出ないの
  見分け方)を書く。このときは再現テストを置かず、第 1 工程を省く
- 期待する結果の拠り所が設計ドキュメントにも既存のテストにも無いと分かったら、それは仕様の変更で
  `flow:bugfix` に合わない作業なので、計画せずに止め、`SKILL.md` フェーズ 1「種類の確定」の 6 に従う

## フェーズ 5: 工程ごとに書かせるものと確かめること

2 つの工程に分ける仕組み(工程の渡し方・第 1 工程のコミット・第 1 工程を省くとき)は `SKILL.md` フェーズ 5。

1. **第 1 工程(`工程: 再現テスト`): 再現テストだけを書かせる。** 修正はさせない
   - 返ってきた検査の出力で、**再現テストを走らせる検査で再現テストだけが落ち、落ち方が計画に
     書いた assert の失敗である**こと、それ以外の検査が通っていることを親が確かめる。再現テストが
     通った・assert 以外(読み込みの失敗・実行時エラー等)で落ちた・他のテストも落ちた、のどれかなら
     再現になっていないので、計画へ戻す
2. **第 2 工程(`工程: 修正`): 修正させる。** 再現テストは書き換えさせない
   - 返ってきたら、親が `SKILL.md` フェーズ 5 の `git diff --exit-code` を走らせる(第 1 工程のテストの
     ファイル = 再現テストのファイル)
   - 同じ再現テストが通っていることを、返ってきた検査の結果で確かめる

**第 1 工程を省いたとき**(フェーズ 3 で自動テストで再現できないとした)は、計画の代わりの確かめ方を
第 2 工程の前と後で行い、前は症状が出て後は出ないことを Issue に書く。

## フェーズ 6: 直しのたびに同じコマンド

採用した指摘を `implementer` に直させたら、そのたびに `SKILL.md` フェーズ 5 の `git diff --exit-code` を
走らせ直す。直しでも再現テストは書き換えさせない。

## フェーズ 7: PR 本文に 2 つの工程のコミット

PR 本文に、**第 1 工程のコミット**(再現テスト)と、第 2 工程以降の**修正のコミット**を並べて書く。
読む人が前者だけをチェックアウトして、テストが落ちることを確かめられるようにする。第 1 工程を
省いたなら、その理由と代わりの確かめ方の結果を書く。
